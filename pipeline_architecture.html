Evidence Builder Satwik
unified_pipeline/evidence/prose_evidence.py → ProseEvidenceBuilder
Input
question text (str) config dict (evidence_path, question_doc_file)
Output — EvidenceResult
EvidenceResult( text = "Kaven Sornwick: Classical Artist…", metadata = {"file_count": 1, "files": ["artist_028…"]} )
Logic (two-path)
Path A — Single-doc mode (preferred): If question_doc_file is set AND the file exists: → read only that one .txt file (~500 tokens) → used for all single-artist questions Path B — All-docs fallback: If question_doc_file is "" (multi-artist / cross-doc questions): → glob all *.txt in evidence_path → join with "\n\n---\n\n" separator → used for CROSS-Qxx questions requiring all artist data
Why single-doc matters: Loading all 250 music documents = ~175,000 tokens per request, which exceeds NVIDIA NIM's context limit and causes connection errors. Single-doc mode keeps input to ~500–600 tokens per request.

Prompt Engine Satwik
run.py build_prompt() + prompts/*.txt templates
Template — llm_only_zero_shot.txt
You are a factual assistant. Answer the question below using only the evidence provided. --- EVIDENCE: {evidence} --- QUESTION: {question} ANSWER FORMAT: {answer_format} --- Provide only the answer value. No labels, no units, no explanation, no extra words.
Template — sql_detour_zero_shot.txt
You are a SQL expert. Write a single SQLite SELECT query that answers the question. DATABASE CONTEXT: {evidence} QUESTION: {question} ANSWER FORMAT: {answer_format} Rules: Write only the SQL. SELECT only. End with semicolon. Note: Only applicable to CSV/IMDB datasets, NOT music/F1 prose datasets.
Template slots filled via Python str.format(). Mode × prompt_style pair selects the template file: (llm_only, zero_shot) → llm_only_zero_shot.txt | (sql_detour, zero_shot) → sql_detour_zero_shot.txt

Model Aliases (config.py)

Retry Logic
• Up to 3 attempts per question • Exponential back-off: sleep × attempt • Non-retryable: 400/401/403/404 errors, bad request, invalid key, context length • Raises ModelCallError after all attempts
Response Normalisation
• Strips <think>…</think> reasoning blocks • Extracts reasoning_content / reasoning fields • Deduplicates reasoning text • Extracts SQL (if sql_detour mode) • Validates SQL (SELECT only, no DDL)
Physical execution: The pipeline runs locally on your Windows machine. The prompt text is sent as an HTTP POST to NVIDIA's cloud servers. The model (Nemotron Ultra 550B) runs on NVIDIA infrastructure. Response travels back over the internet. Average latency: 4–15 seconds per question with 512 max tokens.
ModelResponse (final_text, tokens, latency)

Evaluator Satwik
unified_pipeline/evaluators/exact_match_evaluator.py → ExactMatchEvaluator
Normalisation Steps
1. strip() + lower() 2. remove $ % , (between digits only for comma) 3. collapse multiple whitespace → single space
Comparison
normalise(model_response) == normalise(ground_truth) → returns 1 (match) or 0 (no match)
EvalResult fields
content_exact_match : 1 or 0 row_f1 : same as exact_match (0.0 or 1.0) precision : same recall : same evaluation_status : "evaluated"
Other evaluators (registered)
RowF1Evaluator (CSV row matching) SpanF1Evaluator (NLP span overlap) PartialCreditEvaluator (fuzzy scoring) → selected via eval_strategy in YAML
Known limitation: ExactMatchEvaluator requires the model to return only the bare answer value. Extra words (e.g. "522,249,071 streams") cause a mismatch. The zero_shot prompt is tuned to suppress this with "No labels, no units, no explanation, no extra words."
EvalResult (exact_match, f1, precision, recall)

Each row is appended immediately after the question is answered — if the run crashes at question 50, questions 1–49 are already saved. The pipeline can be re-run with --task_ids to resume only failed questions.

Data Contracts — base.py

Rule: Nobody modifies base.py once agreed upon. Every evidence builder and evaluator inherits from the abstract classes defined here. run.py never imports concrete classes directly — it always goes through the registry in config.py.

@dataclass EvidenceResult

@dataclass
class EvidenceResult:
    text    : str   # prompt-ready evidence string
    metadata: dict  # file_count, files, etc.
Produced by: ProseEvidenceBuilder, CsvEvidenceBuilder (Krittika), RagEvidenceBuilder (Nishit)

@dataclass ModelResponse

@dataclass
class ModelResponse:
    final_text     : str        # the answer text
    reasoning_text : str        # <think> content
    finish_reason  : str
    input_tokens   : int | None
    output_tokens  : int | None
    latency_seconds: float
Produced by: ModelRouter.call()

@dataclass EvalResult

@dataclass
class EvalResult:
    content_exact_match: int         # 1 or 0
    row_f1             : float | None
    precision          : float | None
    recall             : float | None
    evaluation_status  : str         # "evaluated" etc.
Produced by: ExactMatchEvaluator, RowF1Evaluator, etc.

How to Run

Step 1 — One-time data setup (run from Team Project root)

python sprint5_data_setup.py

Step 2 — Configure API credentials

cd LLM_Benchmark_Unified_Framework copy .env.example .env # then open .env and fill in MODEL_API_KEY

Step 3 — Run the benchmark

# Full music run — all 118 questions python run.py --dataset music --model nemotron_ultra --prompt zero_shot # Full F1 run — all 255 questions python run.py --dataset f1_racing --model nemotron_ultra --prompt zero_shot # Test a subset first python run.py --dataset music --model nemotron_ultra --prompt zero_shot --task_ids T01 T02 T03 # SQL detour mode (IMDB only) python run.py --dataset imdb_20 --model nemotron_ultra --mode sql_detour --prompt zero_shot

Step 4 — Read results

results/nemotron_ultra/music_llm_only_zero_shot_metrics.csv → columns: dataset, model, mode, prompt_style, question_id, exact_match, row_f1, precision, recall, eval_status, latency_seconds, input_tokens, output_tokens, model_response
